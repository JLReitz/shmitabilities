# Add knowledge

1. Check the material's persistence. Use ephemeral artifacts only as working evidence and do not add them to the tree. Follow search results to their persistent sources. For code-defined contracts, use online source code at a release tag or commit as the resource.
2. Classify the material:
   - Write a `Reference` for a source-faithful account of one external source.
   - Write a `Concept` for analysis or knowledge derived from references and other concepts.
3. Search existing `resource` values before adding an ordinary source reference. Update the matching ordinary reference when the resource already exists. Before adding a Package or sanctioned execution, add or locate the ordinary source Reference with the same normalized `resource`.
4. Place the document by subject. Add a topic Concept to each topic directory. Organize Reference paths by source boundary, not URL segments; place Package abstracts and package-scoped sanctioned executions under `references/packages/<package>/`, and place other sanctioned executions under the resource domain; add a Reference `index.md` to each new source domain or package directory, and set its `resource` to the complete source represented by that directory.
5. Add the required frontmatter and a structured Markdown body. Write each non-index Reference for use without web access, including its source-defined contracts, field meanings, constraints, procedures, and complete formatted templates. Keep abstracts in `index.md` bodies. Verify each Reference against its online resource when access is available. Add every parent-directory name as a topical tag and at least one additional term tag. Start a new Concept's `history.created` at creation time with `updates: []`. Keep an open Concept body empty.
6. Link each supported claim or instruction to an ordinary source Reference, Package, Command, or Computation as appropriate. All Reference subtypes use the same Concept link rules. Never place an external URL, infrastructure link, or unresolved link in a Concept body. Declare each internal filepath once per document. When a document links one target more than once, use one reference-style definition and repeat its label. An index abstract MAY link to any consumable document outside the directory that contains the index. Put links to documents in that directory or below it in the table of contents.
7. Update the nearest index table of contents with each file and child directory directly beside it except `index.md` and `log.md`. Update a relevant `log.md` when it exists.
8. Check the tree against the conformance rules in `SKILL.md`.
9. Verify modified documents and evaluate confidence and investment with [knowledge-cli](./knowledge-cli.md). Add support for each non-open Concept whose confidence is `0.0`, or make it an open Concept by emptying its body.
