# Restart the shared server

1. From a configured project root, run `bd dolt status` and inspect the reported endpoint. If it says `socket: operation not permitted`, repeat the check in a shell with access to local network sockets; that error does not establish that the server stopped. If it says `connection refused`, check `ss -ltnp` for a listener on the reported port and `pgrep -a -x dolt` for a server process. Resolve an endpoint mismatch or a running process before attempting a restart.
2. When no server is listening, resolve the managed agent root as directed in `SKILL.md`. Confirm `<resolved-agent-root>/beads/dolt/` exists and the project's ignored `.beads/.env` selects that server root. From the configured project root, run `bd dolt start` in a shell with local socket access. Preserve the existing server data and project databases.
3. Run `bd dolt status`, `bd dolt show --json`, and `bd sql 'SHOW DATABASES'` from the same project root. Confirm the server is running, `connection_ok` and `shared_server` are true, and the selected project database appears. If the server exits again, inspect the log and PID file under the resolved `beads/` root before attempting another restart; record the failure without assuming its cause.
